# Data dictionary

All six tables are generated by `scripts/generate_data.py` (coverage) and the
forecast generator described in `docs/BUILD_GUIDE.md`. Nothing in them is real:
every company, person, territory and amount is invented. The generator is seeded,
so the files can be rebuilt identically.

## coverage_accounts.csv (400 rows, one per account)

| column | type | meaning |
|---|---|---|
| account_id | text | A0001 to A0400 |
| account_name, parent_company | text | invented names |
| vertical | text | Financial & Retail, Education, Public Sector |
| segment | text | Strategic, Enterprise, Corporate, Mid-Market |
| country, region | text | United Kingdom or Ireland; eight regions |
| territory_id, territory_name | text | 40 territories, five per region |
| rep_name | text | owning rep; each rep's accounts sum exactly to that rep's opening TAM |
| employee_band | text | headcount band |
| estimated_tam | whole number | total addressable market for the account |
| health | text | Clean or Defect (170 defects) |
| issue_type | text | one of eight defect types, or None |
| issue_severity | text | High, Medium, Low, or None |
| severity_rank | whole number | 3, 2, 1, 0 for sorting |
| tam_at_risk | whole number | TAM sitting on a defective record; 0 when Clean; total 2,968,000 |
| active_bid | text | Yes or No |
| hierarchy_status | text | Verified, Unverified, Pending |
| resolution_status | text | Open, In progress, Resolved, Not required |

Derived in Power Query: `at_risk_flag` (High, Medium, Low or none), `tam_clean` (estimated_tam minus tam_at_risk).

## rep_impact.csv (12 rows, one per rep)

| column | meaning |
|---|---|
| current_tam | opening TAM before correction; sums to 10,613,100 |
| corrected_tam | closing TAM; sums to 10,402,400 |
| tam_delta, tam_delta_pct | corrected minus current; net -210,700 |
| current_quota, corrected_quota, quota_delta | quota before and after; net -50,500 |
| direction | Decrease (7 reps) or Increase (5 reps) |

## tam_movements.csv (48 rows, four per rep)

| column | meaning |
|---|---|
| movement_type | Correction (a data fix) or Reforecast (a real change) |
| movement_reason | Wrong parent, Closed entity, Duplicate, or Headcount change in filings |
| amount | signed; for each rep, Correction plus Reforecast equals tam_delta exactly |

## case_flow.csv (260 rows, one per governance case)

| column | meaning |
|---|---|
| account_id | the defective account the case was raised on; 170 accounts, some with two cases |
| owning_team | Business Analyst, Master Data, Sales Operations, Market Approver |
| implementation_status | Submitted, Approved, Delayed (open, 163) or Implemented, Closed (97) |
| is_stalled | Stalled (96, all open and more than 30 days) or Moving |
| days_open, date_opened, month_opened | age as at 25 September 2026 |

## forecast/ForecastSubmissions/*.csv (47 files, three rows each)

One file per market per week, `FC_W01_Benelux.csv` to `FC_W08_UKandI.csv`.
Columns: market, fiscal_week, week_number, week_ending, product_line (Desktop
Workstation, Mobile Workstation, Workstation Displays), forecast_units,
forecast_revenue. Two deliberate faults: Benelux W08 is missing (it sits in
`late_submission/` for the refresh demo) and France W06 has a negative
Workstation Displays line.

## forecast/Plan/plan_revenue.csv (48 rows)

market, fiscal_week, week_number, week_ending, plan_revenue. Joined to the
forecast on a `key` column (market|fiscal_week) added in Power Query.
